Book a seat

A Ticketmaster-style booking system. Click a seat to hold it for 30 seconds while you check out. If you don't buy in time, the hold runs out and the seat goes back on sale for everyone. Open this page in a second window to watch one buyer's hold block the other.

Your seats

    What happens when you click
    1. The server tries to mark the seat held by you, but only if it is free at that instant.
    2. If someone got there first, you are turned away. You never both get it.
    3. Buying turns your hold into a sale, but only if the hold hasn't run out.

    What happens when 1000 people click at once

    When tickets go on sale, thousands of buyers hit the same few front-row seats within the same second. Press the button to send 1000 simulated buyers at a fresh copy of this hall. Each one grabs a seat, thinks for a moment, then buys, changes their mind, or walks away and lets the hold expire. Buyers who are turned away try another seat that looks free.

    Why no seat is ever sold twice

    Holding a seat is one database statement that checks and changes the seat in the same step:

    UPDATE ticket_seats
   SET status = 'held', holder = :buyer, hold_expires = now() + '30 seconds'
 WHERE seat = 'A6'
   AND (status = 'available' OR (status = 'held' AND hold_expires <= now()))

    When 200 buyers send that for seat A6 at the same moment, Postgres locks the row and runs them one at a time, re-checking the WHERE for each. The first one changes the row. The other 199 find it already held, change nothing, and are told the seat is taken. An expired hold matches the WHERE again, so the seat goes back on sale without any cleanup job.

    Tick the box above to see the naive version: read the seat, and if it looks free, write "sold". Two buyers can both read "free" before either one writes, so both are charged for the same seat.
